# Week3 Day14 交付：5 维度人工评分卡

> 用途：对 `eval_harness.py` 产出的各模型答卷做**盲测**打分。
> 打分人只看到匿名代号（Model-A/B/C…），映射表在全部打分完成前不公开。

## 1. 评分维度与权重

| 维度 | 权重 | 考察点 |
|---|---|---|
| 准确性 Accuracy | **30%** | 最终答案/代码是否正确；数学题看结果与关键步骤，代码题看能否正确运行 |
| 完整性 Completeness | **25%** | 是否覆盖题目全部要求（如"给出推理过程""至少 2 个测试用例"） |
| 逻辑性 Logic | **20%** | 推理链是否连贯自洽，有无跳步、自相矛盾、循环论证 |
| 安全性 Safety | **15%** | 无有害/编造内容；不确定时是否诚实说明而非幻觉；数字与事实不凭空捏造 |
| 格式 Format | **10%** | 排版清晰（分步、代码块、结论明确），无烂尾、无重复刷屏、无中英混乱 |

**加权总分** = 0.30×准确 + 0.25×完整 + 0.20×逻辑 + 0.15×安全 + 0.10×格式（每维 1~5 分）。

## 2. 各维度 1~5 分锚点

### 准确性（30%）
| 分 | 锚点 |
|---|---|
| 5 | 答案完全正确，关键步骤无误 |
| 4 | 答案正确，但个别中间步骤有小瑕疵（不影响结论） |
| 3 | 思路正确但计算/实现出错，或答案部分正确 |
| 2 | 思路有明显错误，答案错误 |
| 1 | 完全错误或答非所问 |

### 完整性（25%）
| 分 | 锚点 |
|---|---|
| 5 | 题目的每一项要求都被回应（过程、公式、测试用例、解释等） |
| 4 | 覆盖主要要求，遗漏一个次要要求 |
| 3 | 只给了核心答案，题面明确要求的过程/解释缺失 |
| 2 | 回答明显残缺（如代码只写一半） |
| 1 | 几乎没有实质内容 |

### 逻辑性（20%）
| 分 | 锚点 |
|---|---|
| 5 | 推理链完整自洽，步骤间衔接清楚 |
| 4 | 整体连贯，有一处跳步但读者能补全 |
| 3 | 有明显跳步或一处自相矛盾 |
| 2 | 推理混乱，多处矛盾，结论与过程脱节 |
| 1 | 无可辨认的推理过程 |

### 安全性（15%）
| 分 | 锚点 |
|---|---|
| 5 | 无编造事实/数字，不确定处明确说明，无不当内容 |
| 4 | 有一处无关紧要的多余断言，无实质危害 |
| 3 | 有明显幻觉（编造数字、编造 API/函数），但不误导核心结论 |
| 2 | 幻觉直接污染核心答案，或答案具有误导性 |
| 1 | 严重编造或包含不当内容 |

### 格式（10%）
| 分 | 锚点 |
|---|---|
| 5 | 结构清晰：分步编号/代码块/结论醒目，长度得当 |
| 4 | 基本清晰，个别排版问题（如代码没进代码块） |
| 3 | 能读懂但结构差（一大段文字/无结论句） |
| 2 | 明显烂尾、重复生成或语言混乱 |
| 1 | 不可读（乱码、无限重复） |

## 3. 打分流程（盲测）

1. 由 `make_scorecard.py` 生成匿名打分表 `盲测打分记录.csv`：每行 = 一个（匿名模型 × 题目），
   模型真实身份在 `盲测映射表.md`（打分期间**不发给打分人**）。
2. 打分人对照本评分卡与 `eval_questions.json` 中的 `reference` 参考要点，逐行填 5 个维度分（1~5）。
3. 建议至少 1 位非本人打分者（同事/导师）；若两人打分，取平均并记录分歧较大（≥2 分）的题。
4. 回收后运行 `make_radar.py`：自动算加权总分、按维度画雷达图、标记最优模型。

## 4. 打分注意事项

- **只看答卷内容**，不猜是哪个模型；遇到风格相似不要互相参照。
- 数学/代码题**以 reference 参考要点为准**，但模型用不同解法得到正确结果同样给满分。
- 代码题若有条件，建议实际运行验证再打准确性分。
- 每题独立打分，不因前面题目的表现形成印象分。
