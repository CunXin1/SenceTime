# Week3 Day11 交付：LoRA 超参对比实验计划表

> 目标：用**控制变量法**科学回答三个问题——LoRA 秩、学习率、训练轮数各取多少最优？
> Goal: answer three questions with single-variable controlled experiments —
> what is the best LoRA rank, learning rate and epoch count?

## 1. 控制变量原则（保证变量唯一）

所有实验中，除被测变量外，以下条件**全部固定**：

| 固定项 | 取值 | 说明 |
|---|---|---|
| 随机种子 seed | 42 | 数据切分 / shuffle / LoRA 初始化全部可复现 |
| 数据集 | `week2_sft_alpaca`（4684 条，Week2 清洗版） | 注册表 `Week2/data/clean/dataset_info.json` |
| 验证集 | `val_size: 0.05`（同种子 → 同切分） | eval loss 是过拟合的核心判据 |
| 等效 batch | 1 × 16 累积 = 16 | |
| 序列处理 | `cutoff_len 2048` + packing + neat_packing | Week2 已验证的提速方案 |
| 调度/预热 | cosine + warmup 10% | |
| 精度 | bf16（RTX 4090） | |
| LoRA 其他 | dropout 0.05，`lora_target: all`，α/r ≡ 2 | α 随秩同步取 2r，避免缩放系数成为混淆变量 |
| 评估频率 | `eval_steps: 50` | Week2 的 200 从未在 ~108 步内触发，改 50 保证每轮 2~3 个 eval 点 |

## 3. 每组假设（实验前预registered，结果出来后逐条验证）

### 组A：LoRA 秩（r=8 vs 32）
- **H-A1**：r=32 可训练参数约为 r=8 的 4 倍（~15M → ~60M），train loss 更低。
- **H-A2**：数据只有 4684 条，若 r=32 的 eval loss 不优于 r=8，说明容量已过剩，
  小数据集上 r=8 即够（这正是社区默认值的由来）。
- **H-A3**：显存峰值与训练耗时随 r 温和上升（LoRA 旁路占比小，涨幅 < 10%）；
  adapter 体积近似随 r 线性增大（~30MB → ~120MB）。

### 组B：学习率（1e-4 vs 2e-4）
- **H-B1**：2e-4 初期下降最快，但可能出现 loss 震荡；若 eval loss 与 1e-4 持平或更差，
  说明 LoRA 在该数据规模下 1e-4~2e-4 已进入平台区。
- **H-B2**：1e-4（基线）综合最稳，预期为最优或与 2e-4 打平。

### 组C：训练轮数（3 vs 5）
- **H-C1**：train loss 随轮数单调下降（ep5 最低）。
- **H-C2**：**eval loss 若在 5 轮时高于 3 轮**即过拟合信号；若 ep5 的 eval loss
  仍在降，说明数据还没榨干，下周可考虑加数据而非加轮数。
- **H-C3**：耗时与轮数近似线性（ep3 ≈ 18min，ep5 ≈ 30min）。

## 5. 时间预算（RTX 4090，按 Week2 实测 3ep≈18min 外推）

| 项 | 估计 |
|---|---|
| Qwen 4 次（18×3 + 30 min，按 10s/步实测外推；3-4 组若内核提速再省 10-20%） | **≈ 1.5 小时** |
| 磁盘 | 4 个 adapter + checkpoint ≈ 1~2 GB（`saves/` 已 gitignore） |

## 6. 最优判定规则（Day14-15 用）

1. **主指标**：eval loss（防过拟合）；train loss 仅作收敛性参考。
2. **平手时**：主观 20 题得分（Day14 盲测）> CEval/CMMLU（Day15）> 训练成本。
3. 每组选出组内最优 → 组合成候选最优配置；若组合与任何已跑配置不同，补跑一次验证
  （避免"各组最优拼起来未必全局最优"的交互效应陷阱）。
