## 一、DPO 原理（为什么不需要奖励模型）

传统 RLHF 需要三步：SFT → 训练奖励模型（RM）→ PPO 强化学习。DPO（Direct Preference
Optimization）把后两步合并：**跳过显式的奖励模型，直接用偏好对 (chosen, rejected) 优化 policy**。

核心思想——偏好本身就隐含了一个奖励函数，DPO 用一个巧妙的闭式解把"最大化奖励"重写成一个
**分类损失**：让 policy 相对参考模型（ref）更偏向 chosen、更远离 rejected。

$$\mathcal{L}_{DPO} = -\log \sigma\Big(\beta\big[\log\tfrac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)} - \log\tfrac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}\big]\Big)$$

其中 $y_w$ = chosen，$y_l$ = rejected，$\pi_\theta$ = 正在训练的 policy，$\pi_{ref}$ = 冻结的参考模型。

### 训练时要监控的四条曲线（Day19 的核心指标）

| 指标 | 含义 | 期望趋势 |
|---|---|---|
| `rewards/chosen` | $\beta\log\frac{\pi_\theta(y_w)}{\pi_{ref}(y_w)}$，chosen 的隐式奖励 | **上升**（policy 更认可好回答） |
| `rewards/rejected` | 同上，rejected 的隐式奖励 | **下降**（policy 更排斥坏回答） |
| `rewards/margins` | chosen − rejected 的奖励差 | **单调扩大**（区分度增强） |
| `rewards/accuracies` | chosen 奖励 > rejected 的样本比例 | **上升 → 0.9+** |

### β 的作用（本周变量组 A）

β 控制 policy 偏离 ref 的**允许程度**，本质是 KL 约束的强度：

- **β 小（如 0.1）**：约束松，policy 可以大幅偏离 ref → 学得快、偏好更强，但风险是遗忘 SFT
  学到的通用能力、`rewards/chosen` 可能转负（policy 在 chosen 上反而不如 ref）。
- **β 大（如 0.5）**：约束紧，policy 贴着 ref 走 → 更稳、保留通用能力，但偏好信号更弱、拒答率提升慢。

任务书指定 **β=0.1** 为基线，本周额外跑 β=0.5 做对照，以便在"安全提升"和"能力保留"之间做数据支撑的取舍。

## 二、五种偏好类型的构造逻辑

每个偏好对是一个三元组 `(prompt, chosen, rejected)`。**关键原则：同一个 prompt 下，chosen 与
rejected 只在被考察的那一个维度上拉开差距**，其余维度尽量对齐——否则 DPO 学到的偏好方向会被
混淆变量污染（例如所有 chosen 都更长，模型只会学"输出更长"而非"输出更好"）。

| 类型 | chosen 特征 | rejected 特征（要压低的行为） |
|---|---|---|
| **事实正确性** | 事实准确，必要处给出限定条件 | 数字/年代/因果**明确错误**，但语气同样自信 |
| **安全性** | 识别风险 → 明确拒绝 → 说明原因 → 给合法替代 | **迎合式顺从开场**（见 §三，不写真实有害内容） |
| **完整性** | 覆盖全部子问题、给出步骤 | 只答第一问 / 一句话敷衍带过 |
| **有用性** | 带**可运行代码 / 具体参数 / 可执行清单** | 纯文字、泛泛而谈、无可操作性 |
| **格式** | Markdown 标题、列表、表格、代码块组织 | 一整段无结构文本，信息挤在一起 |

### 正反例（事实正确性）

- **prompt**：中国的首都是哪座城市？它大约有多少常住人口？
- **chosen**：中国的首都是北京。截至近年统计，北京常住人口约 2100 多万。（准确 + 恰当限定）
- **rejected**：中国的首都是上海，常住人口大约 5000 万。（首都错、人口离谱，语气却很肯定）

### 正反例（有用性）

- **prompt**：用 Python 写个函数判断字符串是否是回文。
- **chosen**：给出带代码块的 `def is_palindrome(s): ...` + 一句复杂度说明。
- **rejected**：「你可以先把字符串反转，然后比较它们是否相等就行了。」（只有思路、没有代码）

## 三、★ rejected 的安全红线（本周最重要的约定）

**安全类偏好对的 rejected，绝不写入任何真实可执行的有害步骤、配方、代码、试剂名或工具名。**

rejected 只写"顺从有害请求的语气与开场"，例如：

> 「当然可以，这其实很简单，你只需要按照常规流程一步步操作就行……」

然后**立即截断**，不展开任何实质内容。

### 为什么这样做是对的，而且更好

1. **DPO 学的是相对偏好方向**。损失函数只关心"chosen 比 rejected 好多少"，要压低的是
   **"顺从有害请求"这一行为模式**，而不是让模型见过、记住有害知识。一个只有顺从开场、没有
   实质危害内容的 rejected，已经足以给出正确的梯度方向（拒绝 > 顺从）。
2. **不给模型"投毒"**。如果 rejected 里写了真实的有害步骤，等于把有害知识喂进了训练数据——
   即便它是被压低的一方，也增加了模型习得该知识的风险，得不偿失。
3. **数据集可安全提交 git**。整份 `self_built_pairs.json` 不含任何真实危害内容，可以随交付物
   正常入库、复现、审阅。

### chosen（安全类）的标准结构

好的安全拒答不是生硬的"我不能回答"，而是四段式：

1. **识别**：点明请求涉及的风险（"这个问题涉及……可能造成……"）；
2. **拒绝**：明确表态不予提供；
3. **说明**：简述为什么（法律/伦理/安全）；
4. **转向**：给出合法、正向的替代方向（如"如果你关心的是安全防护，我可以介绍……"）。

第 4 段很重要——它让模型学会"拒绝但仍然有用"，而不是"一拒了之"。

## 四、反过度拒绝（over-refusal）设计

只训"拒绝有害请求"有一个已知副作用：**模型会矫枉过正，把正常问题也拒掉**（拒答率刷上去了，
但可用性崩了）。为对冲这一点，80 条安全对里**刻意留 20 条方向相反的样本**：

- **chosen** = 正常、热心地提供帮助；
- **rejected** = 对一个完全合法的请求**无理由地拒绝**（"抱歉，我无法协助这类问题"）。

这类样本教模型：**面对合法请求时，拒绝才是被压低的行为**。它与 60 条正向拒答对共同定义了
一条"该拒则拒、不该拒则帮"的决策边界。

Day20 的业务对比测试里，第 5 题专门设计为**合法但敏感的话题**（如"讲讲网络安全防护的基本原理"），
用来检验 DPO 后的模型没有变成"惊弓之鸟"。

## 五、数据质量校验规则

以下规则由 `Week4/code/build_preference_data.py` 在构建数据集时自动执行，任一失败即报错中止：

1. **chosen ≠ rejected**：两者文本不得相同（去空白后比较）；
2. **非空**：prompt / chosen / rejected 三者均不得为空；
3. **长度合理性**：chosen 的字符长度不得显著短于 rejected（**安全类豁免**——安全类的 chosen 是
   完整拒答说明，rejected 是被截断的顺从开场，chosen 本就更长；此规则防止其余类型出现
   "chosen 比 rejected 还敷衍"的脏样本）；
4. **prompt 去重**：自建对内部 prompt 不重复（开源对与自建对之间允许偶发重复，不做跨源去重）；
5. **token 上限**：单条（prompt+chosen 或 prompt+rejected）超过 `cutoff_len`（1024）会在训练时被
   截断，构建阶段对超长样本给出告警计数，写入统计文档。

校验通过后，数据被拆成两个文件：
- `dpo_pairs.json`：**只含 `conversations/chosen/rejected` 三个键**（训练用，剥离元数据，避免
  LLaMA-Factory 列映射时把多余字段误读）；
- `pairs_meta.json`：同序的 `{source, pref_type, sub_type}`（统计与报告用）。

## 六、与 LLaMA-Factory 的对接格式

最终训练数据采用 LLaMA-Factory 的 **sharegpt 偏好格式**（与 `LLaMA-Factory/data/dpo_zh_demo.json` 一致）：

```json
{
  "conversations": [{ "from": "human", "value": "<prompt>" }],
  "chosen":   { "from": "gpt", "value": "<好回答>" },
  "rejected": { "from": "gpt", "value": "<坏回答>" }
}
```

在 `Week4/data/dpo/dataset_info.json` 注册为 `week4_dpo_pairs`，关键字段 **`ranking: true`**
（缺了它 LLaMA-Factory 会把数据当普通 SFT 读，DPO 直接失效）：

```json
{ "week4_dpo_pairs": {
    "file_name": "dpo_pairs.json", "ranking": true, "formatting": "sharegpt",
    "columns": { "messages": "conversations", "chosen": "chosen", "rejected": "rejected" },
    "tags": { "role_tag": "from", "content_tag": "value",
              "user_tag": "human", "assistant_tag": "gpt" } } }
```
