# Day17：偏好数据构造方法论（设计记录）

> 交付物：《偏好数据构造指南.md》。

## 今天做了什么

1. 学习 DPO 原理：理解 chosen/rejected 的构造逻辑，以及为什么 DPO 不需要显式奖励模型——
   偏好本身隐含奖励函数，DPO 用闭式解把"最大化奖励"重写为一个相对偏好的分类损失。
2. 明确训练时要监控的四条曲线：`rewards/chosen`↑、`rewards/rejected`↓、`margins`↑、`accuracies`→1，
   以及 β 如何控制与 ref 的 KL 约束强度（本周变量组 A）。
3. 覆盖 5 种偏好类型的构造标准（事实正确性 / 安全性 / 完整性 / 有用性 / 格式），每类定义 chosen 与
   rejected 的区别特征，并给正反例。

## 关键设计决策（为什么这么做）

1. **安全类 rejected 只写"顺从的语气与开场"，不写任何真实有害内容**。DPO 学的是相对偏好方向，
   要压低的是"顺从有害请求"这一行为模式，而非让模型见过有害知识。附带好处：数据集可安全进 git。
2. **单变量对齐原则**：同一 prompt 下 chosen 与 rejected 只在被考察维度拉开差距，其余对齐——
   否则模型会学到混淆变量（如"输出更长"而非"输出更好"）。
3. **反过度拒绝设计**：安全类里留 20 条方向相反的样本（chosen=正常帮助，rejected=无理由拒绝），
   防止 DPO 把模型训成"什么都拒"。这条在 Day20 业务 Prompt 第 5 题单独检验。
